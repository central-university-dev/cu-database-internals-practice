# Занятие 4. Практические задания — AST и SQL Parsing

Набор из **4 мини-практик** по материалам занятия: построение AST, парсинг выражений, семантика и поддержка INSERT/CREATE TABLE.

---

## Практическое задание 1. Базовые классы AST и простой SELECT

### Цель
Смоделировать минимальное AST для SQL и собрать дерево для запроса `SELECT name FROM users`.

---

### Что нужно сделать
1. Реализовать `toString` методы у каждой AST ноды
2. Написать билдер `AstBuilder.buildSimpleSelect()` для запроса ниже, итогом должен стать метод, который с помощью конструкторов нод просто создаёт конечный объект:
  - `SELECT name FROM users`
3. Реализовать простой вывод дерева `AstBuilder.printAst(AstNode node)`:
  - Формат — дерево с отступами (2 пробела на уровень).
  - Для узлов показывать тип и ключевые поля (например: `SelectStmt(targets=1, from=1)`).
4. ADDITIONAL: если вы быстрее других, то можно реализовать преобразование строки из консоли в AST дерево.

Пример вывода:
```
SelectStmt
  targetList:
    ResTarget(_)
      ColumnRef(name)
  fromClause:
    RangeVar(users)
```

Вывод можно сделать в любом виде, но должен быть читабельным.

---

### Ограничения
- `toString()` у узлов — человекочитаемый, без циклических зависимостей.
- Никаких рефлексий; только явный вывод полей.

## Практическое задание 2. Реализация некоторого WHERE

### Цель
Освоить построение деревьев выражений с учётом приоритета и ассоциативности операторов.

---

### Что нужно сделать
1. Реализовать конструктор сложного WHERE в `WhereBuilder.buildComplexWhere()`: для выражения `age > 20 OR NOT city = 'SPB'`
2. Реализовать красивый рекурсивный вывод выражений: `WhereBuilder.printWhereTree(Expr node, int indent)`
3. ADDITIONAL: если вы быстрее других, то можно реализовать дополнительно `NOT (age > 20 AND city = 'SPB) OR (age < 18 AND city = 'MOSCOW')` и написать на это тесты.

### Требования
1. Соблюсти приоритет: NOT сильнее OR; сравнение сильнее логических операторов.

## Практическое задание 3. Семантическая проверка SELECT

### Цель
Пройти полный цикл семантического анализа простого SELECT.

---

### Что нужно сделать
1. Реализовать SemanticAnalyzer:
   1. Обработать FROM: наличие таблицы, столбцов через менеджер каталога (для этой работы можете воспользоваться менеджером каталогов с предыдущей лекции или написать минимальный in-memory каталог). 
   2. Определить ссылки на столбцы в SELECT и WHERE, проверить их наличие в таблице.
   3. Проверить совместимость типов для операторов (=,>,<,+,-,*,/). 
   4. Если что-то не так — бросить исключение.
2. Написать SemanticTest.main:
   1. Создать каталог и таблицу users(id INT, name TEXT, age INT, city TEXT nullable). 
   2. Собрать AST для SELECT name, age FROM users WHERE age > 18 AND city = 'Moscow'. 
   3. Вызвать analyzer.analyze(ast) и вывести успешный результат.
3. ADDITIONAL: реализовать самостоятельно CREATE и INSERT анализаторы
4. ADDITIONAL: реализовать поддержку нескольких таблиц в FROM (JOIN)

### Критерии приёмки

1. Для валидного запроса — успешный вывод.
2. Для дерева вида SELECT x FROM users → ошибка Unknown column: x.
3. Для отсутствующей таблицы → ошибка Table not found.
4. Для age > 'hi' → ошибка несовместимости типов.
